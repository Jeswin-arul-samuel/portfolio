Agent Deep Dive

Four Specialized AI Agents

🔎

Agent 1: Patent Fetcher

Searches Google Patents via SerpAPI for the research area. Filters to the last 3 years and paginates up to 100 results (10 pages of 10) to balance coverage with API cost.

Tools: SerpAPI Google Patents search
Extracts: Title, publication number, dates, inventors, assignee, snippet, PDF links
Stores: Patent records in patents table with session_id
📑

Agent 2: Innovation Extractor

Downloads patent PDFs using PyMuPDF, chunks the text, generates OpenAI embeddings (text-embedding-3-small, 1536 dims), and uses GPT-4o-mini to extract structured innovations from each patent.

Tools: PyMuPDF (PDF download + chunking), OpenAI Embeddings API
LLM: gpt-4o-mini for extraction (cost-efficient for high volume)
Extracts: Innovation summary, technology used, problem solved
Resilience: Skips patents where PDF download fails — logs warning, does not block pipeline
🧩

Agent 3: Synthesis

Loads all innovations for the session, embeds the original query, and uses pgvector cosine similarity to rank the most relevant innovations. The LLM then identifies patterns, gaps, convergence areas, and emerging trends across the entire landscape.

Tools: pgvector similarity search, LLM synthesis
LLM: gpt-4o-mini for pattern identification
Output: Structured landscape summary (JSONB stored in analyses.synthesis)
🚀

Agent 4: Ideation

Takes the synthesis report and raw innovations as context. Uses GPT-4o (the most capable model) to generate 5–7 novel future innovation ideas. Each idea includes a title, explanation, and patent trail showing which existing patents inspired it.

LLM: gpt-4o for creative ideation (highest capability)
Output: Array of ideas stored in analyses.generated_ideas (JSONB)
Follow-ups: Handles conversational questions using stored analysis context
Cross-domain: Can receive previous analysis context for cross-domain connections

Conversational Intelligence

Beyond One-Shot Analysis

1️⃣ Initial Analysis with Real-Time Status

User submits a research area. The backend creates a session, then the WebSocket connection triggers the full 4-agent pipeline. Status events stream in real-time so users see exactly which agent is working.

Step 1: Patent Fetcher — "Found 47 patents"
Step 2: Innovation Extractor — "Extracted 142 innovations"
Step 3: Synthesis — "Identified 5 key trends"
Step 4: Ideation — "Generating novel ideas..."

2️⃣ Follow-Up Questions via SSE

After the analysis completes, users can ask follow-up questions that stream responses token-by-token via Server-Sent Events. The Ideation Agent uses stored synthesis and ideas as context.

Example follow-ups:
• "Tell me more about idea 3 — the self-healing membranes"
• "Focus on recycling and sustainability innovations"
• "Which ideas have the strongest patent evidence?"
• "How could idea 1 and idea 5 be combined?"

3️⃣ Cross-Domain Analysis

When starting a new analysis, users can choose to "Build on a previous analysis." This loads the old synthesis and ideas as additional context for the Ideation Agent, enabling cross-domain connections.

🔌 Real-Time Communication Stack

WebSocket
Agent status streaming during pipeline execution. Client connects to WS /ws/analysis/:session_id. Receives step-by-step status events in real-time.
SSE
Follow-up response streaming via Server-Sent Events. Tokens stream as data: {"token": "..."}. Provides a ChatGPT-like typing experience.
REST
Session management and result fetching. Create sessions, list past analyses, and retrieve full results after pipeline completion.

What Makes It Different

Key Design Decisions

📊

Evidence-Based Ideation

Ideas aren't random brainstorming. Every generated innovation is grounded in actual patent data. The Ideation Agent receives a synthesized landscape of real trends, gaps, and patterns extracted from up to 100 patents. Each idea includes a patent trail that traces back to the evidence that inspired it.

100 Patents
→
Trends + Gaps
→
Grounded Ideas
🗄️

pgvector Consolidation

Instead of running a separate vector database (Pinecone, Weaviate, etc.), IdeaPoke stores embeddings directly in PostgreSQL using the pgvector extension. One database for structured data AND vector similarity search. This simplifies deployment, reduces infrastructure cost, and eliminates data sync issues between separate stores.

No Pinecone
→
One PostgreSQL
→
Simpler Ops
📡

Real-Time Agent Transparency

Users aren't left waiting behind a spinner. The WebSocket connection streams exactly which agent is working and what it's doing: "Fetching patents...", "Found 47 patents", "Extracting innovations from PDFs...". This builds trust and makes the multi-minute pipeline feel interactive rather than opaque.
